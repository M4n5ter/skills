# 迁移调用方，再删除旧 API（Migrate Callers Then Delete Legacy APIs）

**适用场景：** 在引入新的内部 API、同时仍有旧调用方存在时使用。在同一轮改动中迁移调用方并删除旧 API，而不是保留兼容层。

当我们认定新的 API 才是正确设计时，就在同一轮重构中迁移调用方并移除旧 API，而不是保留兼容层。

**规则：**
- 不要仅仅因为内部调用方仍然存在，就保留旧 API 路径
- 盘点调用方，迁移它们，然后立即删除旧 API
- 将临时适配器视为有明确时限的例外，而不是默认架构
- 更新测试以断言新契约，并删除那些仅用于保护重构前实现细节的测试

**适用条件：**
- 没有外部用户依赖向后兼容性
- 项目能够承受协调进行的破坏性变更
- 新 API 属于简化或重构计划的一部分

同时保留新旧 API 会制造双路径复杂性，拖慢清理，并让代码库变得仿佛只能追加、不能删除。
