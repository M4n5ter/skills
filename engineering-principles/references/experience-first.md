# 体验优先（Experience First）

适用场景：产品、用户体验或功能范围之间需要取舍时。用户的愉悦体验优先于实现方便；宁可交付更少但打磨好的功能，也不要交付更多粗糙功能。

当实现便利与用户的愉悦体验冲突时，选择愉悦体验。

- 每个功能、控件和选项都必须有充分理由
- 少交付，交付得更好：三个功能的精致体验胜过十个功能的粗糙体验
- 先做原型再确定方案：在一次性 HTML 中做设计决策，比在生产代码中便宜
- 把细节做好：过渡、对齐、间距、反馈、错误状态
- 收紧核心循环：每个功能都应服务于核心工作流，否则就不要碍事

用户就是使用工作成果的人。对 UI 而言，是最终用户。对库或内部 API 而言，是导入它的同事。下一位维护代码的工程师也是用户。同等重视他们的体验，并从他们的视角解释影响。

基础应服务于体验。基础性思考决定工作的**顺序**。本原则决定**目标**。
