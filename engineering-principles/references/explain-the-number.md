# 解释测量数字（Explain the Number）

**适用场景：** 在相信、汇报或依据自己测得的数字采取行动之前使用：无论是加速幅度、性能退化、吞吐量、延迟，还是评估结果。找出限制它的因素，并排除实际测量对象并非你以为的那项工作的可能性。

- **问“为什么不能再好一倍？”** 指出限制结果的资源或代码路径，例如某个 CPU 核心、一把锁、磁盘、网络，或负载生成器本身。通过一次运行期间采集的性能剖析或系统计数器找到它，再映射到源代码。仅凭阅读代码得到的猜测，不能算找到了限制因素。如果你说不清这个数字为什么不能再好一倍，就说明你不知道自己测到了什么。
- **列出这个数字还可能测到了什么，并逐项用证据排除。** 常见嫌疑包括：错误、被跳过或命中缓存的工作、根本没有执行的代码、未经调优的一方（仍沿用默认设置）、噪声，以及对端到端结果小到无关紧要的局部。
- **将证据与数字放在一起。** 把运行次数、结果的离散程度和限制因素写进记录，或放进链接所指向的产物中。

对于性能数字，使用 [性能测量检查清单](benchmark-checklist.md)执行完整流程。对于评估结果，对试验提出同样的问题：每次运行是否都真正执行了任务，差距是否在多次试验和不同模型中都成立，以及该场景是否重要。

如果一个数字背后的证据没有运行次数、没有离散程度、没有明确指出限制因素，或者节省的时间大于被改动部分原本消耗的时间，就说明你跳过了这一步。

这不同于[证明它确实可用（Prove It Works）](prove-it-works.md)，后者检查输出是否真实。
