# 测试行为，而非实现（Test Behavior, Not Implementation）

**适用场景：** 编写、修改或保留测试时使用。像代码的使用者那样调用它，并断言使用者看到的确切结果。如果一个测试在所有导入的函数都返回 `undefined` 时仍会通过，就应重写或删除它。

测试应像代码的使用者那样调用代码，并断言使用者看到的确切结果。如果一个测试在所有导入的函数都返回 `undefined` 或错误值时仍会通过，就应重写或删除它。

以下形式无法通过这一检验：

- 断言宽松或没有断言：`toBeDefined`、`toBeTruthy`、`not.toThrow`、`toBeGreaterThan(0)`。
- 只检查是否调用或是否缺失：`toHaveBeenCalled`、`not.toHaveBeenCalled`、`toBeUndefined`、`toEqual([])`。
- 用被测代码计算预期值：`expect(f(a)).toBe(f(a))`。
- 复述常量、配置默认值、表格行或提示词字符串。
- 对测试自己构造的数据进行断言，却没有调用被测对象。

修复方法：在测试主体中用一个具体输入调用被测对象，并断言输出的字面值或具体效果。对于 mock，断言它收到的载荷。对于“没有出现”的情况，同时用另一个输入断言它会出现。对于常量，用一个输入测试读取该常量的机制，而不是复述常量值。

保留表格行之间的关系检查（一个键同时存在于两张表中、父项确实存在）以及 `*.test-d.ts` 类型检查。
