# 面向结果执行（Outcome-Oriented Execution）

适用场景：具有明确阶段边界的计划性重写和迁移。向目标架构收敛，不要用注定要丢弃的兼容代码维持平滑的中间状态。

为预期的、可验证的最终状态优化，而不是维持平滑的中间状态。

**原因：** 让每个中间步骤都完全稳定，往往会产生临时兼容代码，最终变成长期债务。向目标架构收敛，在明确的验证边界证明正确性。

**核心规则：**
- 最终状态的完整性优先于过渡期的稳定性
- 经过计划、范围受控、可逆的中间破坏是可以接受的

**护栏：**
- 将它用于具有明确阶段边界的计划性重写和迁移
- 声明哪些地方允许暂时失效
- 迁移期间，对正在改动的区域保留高信号的检查
- 计划完成时，要求进行完整的静态和运行时验证
