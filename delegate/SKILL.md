name: delegate
description: 使用这个技能，把工作委派给当前 tmux 会话中的独立交互式 AI Agent TUI 会话。
---

## 核心规则

1. 默认保持交互式委派：使用 `codex ...`，不要使用 `codex exec ...`。如果当前不是 codex，则选择相似命令，如 opencode 场景下使用 `opencode --prompt ...`，避免 `opencode run ...` 这类用于一次性任务的命令。
2. 默认在当前 tmux 会话中新建窗口，不要新建 tmux 会话。
3. 除非用户明确要求基于文件交接，否则不要写入 `/tmp` 下的交接文件。
4. 提示词必须自包含：包含任务目标、当前工作目录、重要文件、关键信息、限制条件、预期行为和验证命令。
5. 明确告诉被委派的会话：是要实现、讨论、调研，还是避免修改代码。

## 工作流程

1. 确认当前 tmux 会话：

```bash
tmux display-message -p '#S'
```

2. 如果命令失败，说明当前不在 tmux 会话中。此时只问一个简短问题：是创建新的 tmux 会话，还是改用普通 spawn subagent 类工具。

3. 对每条被委派的工作线程，在当前 tmux 会话中新建一个交互式窗口：

```bash
tmux new-window -t '<session>:' -n '<short-name>' -c '<workspace>' "opencode --prompt '<self-contained prompt>'"
```

4. 使用稳定、简短的窗口名，例如 `run-lifecycle`、`flue-events`、`api-design` 或 `review-fix`。

5. 如果之前误创建了分离式委派会话，也就是错误的新 tmux 会话，应先清理掉，再创建正确的窗口：

```bash
tmux kill-session -t '<wrong-session>' 2>/dev/null
```

6. 创建窗口后，向用户报告窗口名称，并用一句话说明每个委派提示词的任务内容。

## 提示词模板

每个提示词（即命令中的 `...` 部分）使用下面这种结构：

```text
<实现|调研|讨论|审查> <具体任务>，工作目录：<workspace>。

背景：<简要说明当前状态、关键信息、相关未提交改动，或已经做出的决策>。

先阅读：<重要的本地文件和参考仓库>。

限制条件：<包管理器要求、仅讨论时不要改代码、代码风格规则、安全限制等>。

预期结果：<希望被委派会话产出什么内容，或完成什么修改>。

验证方式：<需要运行的命令；如果只是讨论任务，则说明无需验证>。
```

## 命令安全

1. 对会话名、窗口名、工作目录路径和提示词都要正确加引号。
2. 默认每个委派任务使用一次独立的 `tmux new-window` 调用；只有在必须指向同一个当前会话时，才可以把多个调用串联起来。
3. 除非用户明确要求非交互式执行，否则不要使用 `opencode run`。
4. 除非用户明确要求创建一个新的独立 tmux 会话，否则不要使用 detached 模式的 `tmux new-session -d`。
